# Design Specification — MaraudersPPT Skill

This document defines the **design principles and specific specifications** of MaraudersPPT Skill.
**Overrides** the design system of PRD (prd-md-to-pptx-skill.md) Section 7.

---

## 0) Core design philosophy

> **White background + black text is the default.**
> For us, information delivery is key. The key is not color expression, but **font size, layout, and readability**.
> **Output is static PDF**. No animations, transition effects, buttons, or interactive elements are needed.
> **The images included in the original MD file must be used**. Do not omit or replace with text.

---

## 1) 8 major design principles

| # |principle|explanation|
|---|------|------|
| 1 |**Minimize Color**|White background + black text is the default. Emphasis is Bold + light red only at word level|
| 2 |**Readability is top priority**|All design decisions are based on readability. Contrast, margins, font size|
| 3 |**Version control required**|At each creation, `v{major}.{minor}_filename` is output in a dedicated folder next to the original MD.|
| 4 |**Clear hierarchy**|Header/body is distinguished by font size and weight. No dependence on color|
| 5 |**Active use of images**|Image Creation/Web Download. Charts and infographics are implemented and inserted using HTML|
| 6 |**High resolution horizontal**|Based on 16:9, 1920x1080. Unbreakable size for large monitors/projectors|
| 7 |**1-2 topics per slide**|Up to two topics per page. If there are more than 3, be sure to split them.|
| 8 |**Excluding AI-generated feeling**|Vibe coding/AI dashboard emotions are prohibited. Understated design at the level of corporate presentation materials|
| — |**Modified expression/quantitative expression**|Avoid sentence-type text. Bullet points + numerical/ratio/comparison focus|

### 1.1 Anti-Vibe-Coding Rules

> **Strictly excludes the typical “Shadcn/Tailwind dashboard” style generated by AI.**
> Presentations is not a web app. The standard is restrained company announcement data at the level of McKinsey/BCG.

|forbidden pattern|reason|alternative plan|
|-----------|------|------|
|`border-radius: 8px~16px` (round card)|Representative visual fingerprints of AI-generated dashboards|`border-radius: 2px` (fine rounding) or `0`|
|`background: #FAFAFA` Card Background|“Soft cards” used by all AI templates|`background: #FFFFFF` (pure white)|
|`::before` Decoration Bar (top 4px color bar)|SaaS Dashboard KPI Card Typography|`border-left: 4px solid` (highlight left line) or remove|
| `text-transform: uppercase` + `letter-spacing: 2px+` |AI’s favorite “small cap label”|Normal case + appropriate font size|
|`#999999`, `#BBBBBB`, `#CCCCCC` text|Excessively faint text → reduced readability|At least `#888888`, main text at least `#555555`|
|Emoji background box (`background: #F0F0F0` + rounded corners)|Notion/AI app icon style|Direct emoji display, no background|
|`#EBEBEB` border|“Soft borders” in AI templates|`#E0E0E0` (conforms to design palette)|

**Key Principle**: Minimize decoration, create hierarchy with typography and white space. Don't try to make it "pretty" with cards, shadows, gradients, and rounded corners.

## 2) Color Palette

### 2.1 Basic Palette — 2 basic colors + 1 color limited accent

|role|color| HEX |usage rate|use|
|------|------|-----|-----------|------|
|**background**| White | `#FFFFFF` | 70% |slide background|
|**Text**| Black | `#1A1A1A` | 28% |Title, body, structure — all basic text|
|**stress**| Soft Red | `#D94F4F` | 2% |**Word Level** Emphasis only. Bold parallel required|

### 2.2 Secondary tones (black and white derivatives)

|use|color| HEX |apply|
|------|------|-----|------|
|subtext| Dark Gray | `#555555` |Additional explanation, level 2 bullet|
|Caption/Source| Medium Gray | `#888888` |Footnotes, data sources|
|category background| Near White | `#F5F5F5` |AI Hint block, code block background|
|section divider| Light Gray | `#E0E0E0` |Horizontal divider, table border|
|Section division background| Charcoal | `#2C2C2C` |section-divider slide only|

### 2.3 Rules for using accent colors — extremely limited

Accent color (`#D94F4F` Soft Red) is used **at word level only**:

```
allowance:
  "Improved processing speed <bold+red>3 seconds → 0.8 seconds</bold+red>" ← Numerical words only
  "Failure rate <bold+red>reduced by 73%</bold+red>" ← KPI numbers only
  AI Hint badge text ← inside badge only

prohibition:
  Color the entire title in red ← The title is always #1A1A1A
  Color the entire sentence in red ← Prohibit application on a per-sentence basis
  Use as background color ← Do not apply to background
  Used for borders/lines ← Do not apply to structural elements
  2 or more places per slide ← Up to 1 place
```

### 2.4 Prohibitions

- Simultaneous use of 4 or more colors
- gradient background
- Apply color to sentence/title unit
- Use of color for decorative purposes
- Use accent color in more than 2 places per slide
- `border-radius: 8px` or higher (maximum `2px` on cards/elements)
- `background: #FAFAFA` card background (use pure white `#FFFFFF`)
- `text-transform: uppercase` + excessive `letter-spacing` (AI dashboard pattern)
- Text with a brightness of `#999999` or less (`#888888` is the minimum contrast for text, body text is `#555555` or higher)
- Add background box to emoji/icon (`background: #F0F0F0` + rounded corners)
- `::before`/`::after` Decorative bar (Saas dashboard pattern, such as top color bar)

### 3.1 Font selection

|use|font|reason|

### 3.3 Font size system

|element| Weight | Size | Line-Height | Color |note|
|------|--------|------|-------------|-------|------|
|**Main Title**| ExtraBold (800) | 36pt | 44pt (1.22×) | `#1A1A1A` |Title slide only, letter-spacing: -0.5px|
|**Section Header**| Bold (700) | 28pt | 36pt (1.29×) | `#1A1A1A` |Section separator slide, letter-spacing: -0.3px|
|**Slide Title**| Bold (700) | 24pt | 32pt (1.33×) | `#1A1A1A` |Normal slide top|
|**Subheader**| SemiBold (600) | 20pt | 28pt (1.40×) | `#1A1A1A` |H3 level|
|**Text (Level 1 Bullet)**| Regular (400) | 18pt | 28pt (1.56×) | `#1A1A1A` |Main bullet points|
|**Main Text (Level 2 Bullet)**| Regular (400) | 16pt | 24pt (1.50×) | `#555555` |secondary explanation|
|**Emphasis words**| Bold (700) |same size|identification| `#D94F4F` |Key Figures — Just Words|
|**Caption/Label**| Light (300) | 12pt | 16pt (1.33×) | `#888888` |Data sources, footnotes|
|**cord**| Regular (Mono) | 13pt | 20pt (1.54×) | `#D4D4D4` |Inside the code block|
|**Slide number**| Light (300) | 10pt | 14pt | `#888888` |Bottom right, `{current}/{total}`|

### 3.4 Typographic Proportion Rules

- **Title: Body = 1.5:1 or higher** (24pt: 18pt = 1.33 → minimum meets)
- **Minimum text size: 16pt** (based on projector/large screen)
- **Minimum size of content text in charts/infographics: 16px** (except for slide numbers 10pt and captions/footnotes 12pt)
- **Font size types per slide: Up to 3** (Title + Body + Caption)
- **Use Bold: only 1-2 places per slide** (overuse destroys hierarchy)
- **Large text letter-spacing**: Apply negative letter-spacing for 28pt or more (reduce visual density)
- **Body line-height**: 1.5~1.6× (optimal readability in a presentation environment)
- Don't use **`text-transform: uppercase`**: Do not apply capitalization to chart labels.
- **Output Language Rule**: The generated PPT follows the source Markdown's language. This skill does not translate content.

## 5) Slide layout

### 5.1 Basic specifications

|item|value|note|
|------|-----|------|
|ratio| **16:9** |fix. 4:3 not supported|
|Dimensions (PPT)| 13.333" × 7.5" (33.87cm × 19.05cm) |PowerPoint standard 16:9|
|HTML Render Resolution| **1920 × 1080 px** |Full HD. Large monitor compatible|
|Margin (top, bottom, left and right)|**Minimum 0.7"** (1.78cm)|Content area is placed inside only|
|title area height|Top 15%|Slide top fixed position|
|body area|Top 20% ~ Bottom 90%|Below the title, above the footnotes|
|Footnotes/Source Area|Bottom 5%|8~10pt, right aligned|

### 5.2 Content rules per slide

|rule|standard|When exceeded|
|------|------|---------|
|**Number of topics**|Up to **2**|Be sure to split slides|
|**Bullet Point**|Up to **4** (optimum 3)|automatic split|
|**Overlapping Bullets**|Up to **1 level**|2nd stage or more → flattening|
|**Table Row**|Up to **5 rows**|Split or Move Appendices|
|**Table Columns**|Up to **4 rows**|Extract only key columns|
|**Number of lines of code**|Up to **12 lines**|Split or extract only the core|
|**60 second rule**|Understand slides ≤ 60 seconds|Minimize content|
|**Continuous Text**|Up to **2 photos in a row**|3rd switch to visual slide|

### 5.3 Spacing between content (based on 8px grid)

> **All spacing is standardized to multiples of 8px**. (8, 16, 24, 32, 40, 48, 56, 64…)

|between elements|interval|8px multiple|
|---------|------|----------|
|Title → First Content| 0.4" (32px) | 32px (4×) |
|bullet liver| 0.2" (16px) | 16px (2×) |
|Between content blocks (bullet → table, etc.)| 0.3" (24px) | 24px (3×) |
|Image → Text (2-column layout)| 0.3" (24px) | 24px (3×) |
|Between small groups within sections| 0.15" (8px) | 8px (1×) |
|Between infographic elements| 0.2" (16px) | 16px (2×) |

### 5.4 Sorting Rules

- **All text: left-aligned** (center-align only for title/section separation slides)
- **Title position: fixed between slides** (never move)
- **Grid Alignment**: All elements snap to a consistent grid

### 5.5 Layout Integrity — NEVER BREAK

> **Layout systems should never break**
> The rules below apply to all slides without exception, and if violated, the slides will be regenerated.

#### 5.5.1 Zero-Tolerance Rules

|rule|explanation|Action in case of violation|
|------|------|-------------|
|**No overflow**|All text/images must be within slide boundaries (0.7" margins)|Reduce fonts or split slides|
|**No overlap**|No element must overlap any other element (including z-index conflicts)|Rearrange or split elements|
|**No deviation from alignment**|All elements must snap to the grid system|Grid Reorder|
|**Do not move title position**|Slide titles are always fixed to the same coordinates|Force restoration of coordinates|
|**No margin encroachment**|Content must not violate the 0.7" safe area|Collapse/Split Content|

#### 5.5.2 Font size reduction cascade

When text overflow occurs, respond in the following order:

```
Step 1: Body font 18pt → 16pt (minimum limit)
Step 2: Subheader 20pt → 18pt
Step 3: Reduce the number of bullets (maximum 4 → 3 → 2)
Step 4: Force split slide
```

> **Title (24pt) and caption (12pt) are never reduced.**

#### 5.5.3 Element priority (in case of conflict)

|priority|element|explanation|
|---------|------|------|
| 1 |subject area|Always in fixed position, never moved|
| 2 |Margin (0.7")|Inviolable|
| 3 |body text|Priority over image|
| 4 |Images/Charts|collapsible|
| 5 |Caption/Source|Can be omitted first|

### 5.6 Automated Validation of Layout

After creating each slide, we automatically verify the following:

|Verification items|method|In case of failure|
|----------|------|--------|
|boundary check|Calculate if all elements (x, y, w, h) are within safe area|regenerate|
|Overlap check|Check whether a pair of elements intersects the bounding box|Regenerate after relocation|
|Text truncation|Compare actual height vs allocated area after text rendering|Font reduction cascade|
|grid sort|Element coordinates are snapped to grid points|Coordinate correction|
|image ratio|Make sure there is no distortion of the original ratio|Resize after restoring proportions|

> If verification fails, regenerate up to 3 times**. If it fails even after 3 attempts, take the best result + log warnings.

### 6.7 Slide flow rules

#### 6.7.2 Early deployment of infographics (FRONT-VISUAL)

Place at least one infographic in the **first 30%** of all slides:
- Move slides with high visual impact (KPI Cards, Bar Chart, Comparison) forward

#### 6.7.3 Automatic appendix separation (AUTO-APPENDIX)

Detailed data is separated from the text and moved to the appendix section:

|QA Checklist|Core 3 items only + "Full list: see appendix"|
|Dependencies/Technology Stack Details|Summary of key points only|
|Reference data/original figures|Keep only core KPIs in the text|

The appendix is ​​placed after slide `appendix-divider`, and can be used in the "A1, A2..." format separately from the main slide number.

## 8) Bullet-Point Style Rules

### 8.1 Slide title = Action title

All slide titles must be **complete sentences containing a conclusion**:

|❌ Subject-type titles (prohibited)|✅ Action title (required)|
|---------------------|---------------------|
|Market Status|Domestic market growing 12% per year, expected to double in size within 3 years|
|Competitor Analysis|Gain an advantage over competitors in 4 out of 6 core criteria|
|technology stack|Processing speed can be improved by 3 times with Go + PostgreSQL combination|

### 8.2 Bullet writing rules

```
[Action title — up to 15 words, complete sentences including verbs]
├── • Key point 1 — Include numbers/data
│ └── ◦ Secondary evidence (indent, small size)
├── • Key point 2 — Include numbers/data
└── • Key point 3 — Include numbers/data

[Source: Data source, year] ← Must be indicated
```

> **Bullet count rule**: Optimum 3 per slide, maximum 4. 5 or more must be split.

### 8.3 Text writing principles

|principle|rule|example|
|------|------|------|
|**Numerical precedence**|Place numbers in front of bullets|“Sales increased by 23%” (O) / “Sales increased” (X)|
|**Parallel Structure**|All bullets have the same grammatical form|Noun-type unification or verb-type unification|
|**1 bullet 1 idea**|No “and/and” in bullets.|Separate into 2 bullets|
|**Avoid sentence type**|No endings such as “~ did” and “is”|Noun ending ("increase", "introduce", "apply")|
|**Core Bold**|The 1 most important number in Bullet: Bold|“Improved processing speed **3 seconds → 0.8 seconds**”|

- **Replacing or omitting images with text is strictly prohibited**

### 15.6 Content→Visualization automatic mapping rules

#### 15.6.1 Core principles

- The mode is based on **AGGRESSIVE**.
- If the pattern matches, it must be converted into a visualization template.
- Text fallback is only allowed under pattern matching failure or explicit override conditions.

#### 15.6.2 Pattern detection rules

|pattern id|trigger condition|Visualization type|Example input|reliability|
|---------|-----------|-----------|---------|-------|
| `NUM-COMPARE` |3+ Each item includes figures (%, number of cases, amount)| Horizontal Bar Chart (`.bar-chart-h`) | "Q1: 87%, Q2: 64%, Q3: 92%" | High |
| `PCT-BREAKDOWN` |Percentage sum of 2-5 items is 90-110%| Donut Chart (`.donut-chart`) | "APAC 42%, EMEA 31%, Americas 27%" | High |
| `SEQ-STEPS` |3-8 sequential steps (number, arrow, then, step N)| Process Flow (`.process-flow`) |“Input → Parse → Mapping → Generation → Output”| High |
| `BEFORE-AFTER` |Comparison of 2 categories (vs, existing/improved, before/after)| Comparison (`.comparison`) |"Existing: 30 minutes manual work / Skill: 1-3 minutes automatic"| High |
| `KEY-METRIC` |1-4 key figures + labels + modifiers| KPI Cards (`.kpi-grid`) |“Conversion success rate 95%, structural accuracy 100%”| High |
| `CATEGORY-LIST` |4-8 short items (≤6 words each), categorical in nature, no numbers.| Icon Grid (`.icon-grid`) |“Development team lead, planner, CTO/VP, AI user”| Medium |
| `CHRONOLOGICAL` |3+ Events by Date/Time/Phase + Chronological Order| Timeline (`.timeline`) |“Phase 1: MVP, Phase 2: Chart, Phase 3: AI”| Medium |
| `NARROWING-STAGES` |Quantity decreases in steps 3-6 (Inflow → Conversion → Purchase)| Funnel (`.funnel`) |“Cognition 10K → Interest 7.5K → Decision 5K → Action 2.5K”| Medium |

#### 15.6.3 Prioritization

If multiple patterns are matched simultaneously, the final template is determined in the order below.

1. Prioritize highly reliable patterns (High)
2. In case of a reliability tie, priority is given to visualizations with less text.
3. If the score is still tied, the fixed priorities below apply.

`NUM-COMPARE` > `PCT-BREAKDOWN` > `KEY-METRIC` > `SEQ-STEPS` > `BEFORE-AFTER` > `CHRONOLOGICAL` > `CATEGORY-LIST` > `NARROWING-STAGES`

#### 15.6.4 Conversion Exception (Override)

- If there is a `<!-- keep-text -->` annotation in Markdown, that block will skip visualization conversion.
- For heterogeneous data tables with more than 5 columns or 8 rows, the original table is maintained.
- Reference tables that require accurate cell value references maintain the original table.

#### 15.6.5 Visualization slide constraints

- The text is limited to 40 words or less. (excluding chart labels/data)
- Bullets or labels are limited to 7 words per item.
- Chart categories are limited to a maximum of 5.
- Secure at least 20% of the total area of ​​the slide as blank space.
- Only one visualization is allowed per slide. (2 charts prohibited)
- The action title is required and must be written as a complete sentence, including verbs, of less than 15 words.

#### 15.6.6 Data Extraction Rules

- Numbers: Extract all numbers and preserve units. (`%`, `$`, `x`, `pt`)
- Label: Use the shortest possible form and abbreviate if it exceeds 7 words.
- Source: Preserve the original data source as a caption.

## 17) Environmental Detection & Model Guidance (IDE Detection & Model Guidance)

### 17.1 Core principles

> For AI image creation, the **Gemini Pro** (`gemini-2.5-pro`) model is required.
> The model conversion method varies depending on the IDE environment.

|environment|Image generation model|PPT conversion model|Model conversion method|
|------|----------------|--------------|---------------|
|**Cursor** (non-OpenCode)| Gemini Pro |Gemini Pro (All)|Manually switch users (pre-check)|
| **OpenCode** |Gemini Pro (background)|Maintain user selection model|Automatic background task|

### 17.2 Cursor IDE Workflow

In Cursor and other non-OpenCode environments, models cannot be switched at runtime.
Therefore, you must ask the user to switch models **before starting the task**.

#### Required pre-message (Blocking)

Before starting PPT conversion, **MUST** print the message below and wait for user confirmation:

```
⚠️ Gemini Pro model selection required

This PPT conversion task requires Gemini Pro model for AI image creation.
Please switch your current model to Gemini Pro (gemini-2.5-pro) and then proceed.

How to switch models: [IDE Settings] → [Select Model] → Select Gemini Pro

After completing the conversion, please enter “Continue” or “Proceed”.
```

- **Never** start the conversion until the user sends a confirmation response
- Check keywords: `"continue"`, `"proceed"`, `"continue"`, `"ok"`, `"yes"`, `"done"`

### 17.3 OpenCode Workflow

In OpenCode, only image creation is executed as a separate model through a background task.

#### Main pipeline (user-selected model)

```
MD parsing → slide mapping → HTML generation → PPTX conversion → layout verification
```

#### Image Creation (Background — Gemini Pro)

```
Step 1: The main pipeline creates a list of slides that require images.
Step 2: Create a list of image creation prompts
Step 3: Spawn background task (Gemini Pro model)
        → task(run_in_background=true)
Step 4: Run NanoBanana Pro /generate in the background
Step 5: Save the creation result to assets/
Step 6: The main pipeline collects results using background_output() and inserts them into PPTX.
```

### 17.4 Environmental Sensing Methods

|Detection criteria| OpenCode |Cursor / Other|
|----------|----------|--------------|
|Availability of `task()` function|✅ Available|❌ Not available|
|Background task support| ✅ | ❌ |
|Model Runtime Switching| ✅ | ❌ |

Detection logic: Determine OpenCode/non-OpenCode based on whether background task API is available.
If not available → Cursor workflow (17.2) applied.
