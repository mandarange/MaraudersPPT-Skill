# Design Specification — MaraudersPPT Skill

This document defines the **design principles and specific specifications** of MaraudersPPT Skill.
**Overrides** the design system of PRD (prd-md-to-pptx-skill.md) Section 7.

---

## 0) Core design philosophy

> **White background + black text is the default.**
> Information delivery is the priority — **font size, layout, and readability** matter more than color.
> **Output is static PDF**. No animations, transitions, buttons, or interactive elements.
> **Original MD images must be preserved**. Never omit or replace with text.

---

## 1) 8 major design principles

| #   | principle                             | explanation                                                                                                                  |
| --- | ------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------- |
| 1   | **Minimize Color**                    | White background + black text is the default. Emphasis is Bold + light red only at word level                                |
| 2   | **Readability is top priority**       | All design decisions are judged based on readability. Contrast, margins, font size                                           |
| 3   | **Version control required**          | At each Generate, `v{major}.{minor}_filename` Output is created in a dedicated folder next to the original MD.               |
| 4   | **Clear hierarchy**                   | Header/body is distinguished by font size and weight. No dependence on color                                                 |
| 5   | **Active use of images**              | Image Generation/Web Download. Charts and infographics are implemented and inserted using HTML                               |
| 6   | **High resolution horizontal**        | Based on 16:9, 1920x1080. Unbreakable size for large monitors/projectors                                                     |
| 7   | **1-2 topics per slide**              | Up to two topics per page. If there are more than 3, be sure to split them.                                                  |
| 8   | **No AI-Generated Aesthetic**         | Vibe-coding / AI dashboard aesthetics are prohibited. Target: restrained corporate presentation quality (McKinsey/BCG level) |
| —   | **Bullet-Point & Quantitative Style** | Avoid sentence-form text. Bullet points + numerical/ratio/comparison focus                                                   |

### 1.1 Anti-Vibe-Coding Rules

> **The typical “Shadcn/Tailwind dashboard” style generated by AI is completely excluded.**
> Presentations are not web apps. The standard is restrained corporate presentation material at McKinsey/BCG quality.

| Forbidden Pattern                                              | Reason                                              | Alternative                                            |
| -------------------------------------------------------------- | --------------------------------------------------- | ------------------------------------------------------ |
| `border-radius: 8px~16px` (rounded cards)                      | Signature visual pattern of AI-generated dashboards | `border-radius: 2px` (subtle rounding) or `0`          |
| `background: #FAFAFA` card backgrounds                         | "Soft card" style common to AI templates            | `background: #FFFFFF` (pure white)                     |
| `::before` decorative bar (top 4px color bar)                  | SaaS dashboard KPI card pattern                     | `border-left: 4px solid` (left accent line) or removed |
| `text-transform: uppercase` + `letter-spacing: 2px+`           | AI's typical "small cap label" pattern              | Normal case + appropriate font size                    |
| `#999999`, `#BBBBBB`, `#CCCCCC` text                           | Excessively faint text → reduced readability        | At least `#888888`, body at least `#555555`            |
| Emoji background box (`background: #F0F0F0` + rounded corners) | Notion/AI app icon style                            | Plain emoji display, no background                     |
| `#EBEBEB` border                                               | "Soft border" pattern in AI templates               | `#E0E0E0` (design palette compliant)                   |

**Key Principle**: Minimize decoration, create hierarchy with typography and white space. Don't try to make it "pretty" with cards, shadows, gradients, and rounded corners.

## 2) Color Palette

### 2.1 Basic Palette — 2 basic colors + 1 color limited accent

| role           | color    | HEX       | usage rate | use                                                  |
| -------------- | -------- | --------- | ---------- | ---------------------------------------------------- |
| **background** | White    | `#FFFFFF` | 70%        | slide background                                     |
| **Text**       | Black    | `#1A1A1A` | 28%        | Title, body, structure — all basic text              |
| **stress**     | Soft Red | `#D94F4F` | 2%         | **Word Level** Emphasis only. Bold parallel required |

### 2.2 Secondary tones (black and white derivatives)

| Purpose                     | Color       | HEX       | apply                                  |
| --------------------------- | ----------- | --------- | -------------------------------------- |
| subtext                     | Dark Gray   | `#555555` | Additional explanation, level 2 bullet |
| Caption/Source              | Medium Gray | `#888888` | Footnotes, data sources                |
| category background         | Near White  | `#F5F5F5` | AI Hint block, code block background   |
| section divider             | Light Gray  | `#E0E0E0` | Horizontal divider, table border       |
| Section division background | Charcoal    | `#2C2C2C` | section-divider slide only             |

### 2.3 Rules for using accent colors — extremely limited

Accent color (`#D94F4F` Soft Red) is used **at word level only**:

```
allowance:
"Improved processing speed <bold+red>3 seconds → 0.8 seconds</bold+red>" ← Numerical words only
"Failure rate <bold+red>reduced by 73%</bold+red>" ← KPI numbers only
AI Hint badge text ← inside badge only

prohibition:
Color the entire title in red ← The title is always #1A1A1A
Color the entire sentence in red ← Prohibit application on a per-sentence basis
Use as background color ← Do not apply to background
Used for borders/lines ← Do not apply to structural elements
2 or more places per slide ← Up to 1 place
```

### 2.4 Prohibitions

- Simultaneous use of 4 or more colors
- gradient background
- Apply color to sentence/title unit
- Use of color for decorative purposes
- Use accent color in more than 2 places per slide
- `border-radius: 8px` or higher (up to `2px` on cards/elements)
- `background: #FAFAFA` card background (use pure white `#FFFFFF`)
- `text-transform: uppercase` + excessive `letter-spacing` (AI dashboard pattern)
- Text lighter than `#999999` (`#888888` is minimum contrast for text, body is `#555555` or higher)
- Emoji/icon background boxes (`background: #F0F0F0` + rounded corners)
- `::before`/`::after` Decorative bar (Saas dashboard pattern, such as top colored bar)

## 3) Typography

### 3.1 Font selection

| Purpose       | Font                                  | Reason                                                                                                                                                                                                        |
| ------------- | ------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Main Font** | **Pretendard**                        | Top-ranked for combined Korean + English readability. Based on Noto Sans CJK KR + Inter. 9 weight. SIL OFL License (Free for commercial use). Adopted by the Korean government’s official UI/UX design system |
| **Code Font** | **JetBrains Mono** or **Courier New** | Code readability. JetBrains Mono first, Courier New fallback if not installed                                                                                                                                 |

### 3.2 Fallback Chain

Embed Pretendard in PDF, but fallback for non-installed environments:

```
Pretendard → Apple SD Gothic Neo → Malgun Gothic → Noto Sans KR → sans-serif
```

| Environment                        | Fallback Font       |
| ---------------------------------- | ------------------- |
| macOS (Pretendard not installed)   | Apple SD Gothic Neo |
| Windows (Pretendard not installed) | Malgun Gothic       |
| Linux / Other                      | Noto Sans KR        |

### 3.3 Font size system

| Element                        | Weight          | Size      | Line-Height    | Color     | note                                            |
| ------------------------------ | --------------- | --------- | -------------- | --------- | ----------------------------------------------- |
| **Main Title**                 | ExtraBold (800) | 36pt      | 44pt (1.22×)   | `#1A1A1A` | Title slide only, letter-spacing: -0.5px        |
| **Section Header**             | Bold (700)      | 28pt      | 36pt (1.29×)   | `#1A1A1A` | Section separator slide, letter-spacing: -0.3px |
| **Slide Title**                | Bold (700)      | 24pt      | 32pt (1.33×)   | `#1A1A1A` | Normal slide top                                |
| **Subheader**                  | SemiBold (600)  | 20pt      | 28pt (1.40×)   | `#1A1A1A` | H3 level                                        |
| **Text (Level 1 Bullet)**      | Regular (400)   | 18pt      | 28pt (1.56×)   | `#1A1A1A` | Main bullet points                              |
| **Main Text (Level 2 Bullet)** | Regular (400)   | 16pt      | 24pt (1.50×)   | `#555555` | secondary explanation                           |
| **Emphasis words**             | Bold (700)      | same size | identification | `#D94F4F` | Key Figures — Just Words                        |
| **Caption/Label**              | Light (300)     | 12pt      | 16pt (1.33×)   | `#888888` | Data sources, footnotes                         |
| **Code**                       | Regular (Mono)  | 13pt      | 20pt (1.54×)   | `#D4D4D4` | Inside the code block                           |
| **Slide number**               | Light (300)     | 10pt      | 14pt           | `#888888` | Bottom right, `{current}/{total}`               |

### 3.4 Typographic Proportion Rules

- **Title: Body = 1.5:1 or higher** (24pt: 18pt = 1.33 → minimum meets)
- **Minimum text size: 16pt** (based on projector/large screen)
- **Minimum size of content text in charts/infographics: 16px** (except for slide numbers 10pt and captions/footnotes 12pt)
- **Font size types per slide: Up to 3** (Title + Body + Caption)
- **Use Bold: only 1-2 places per slide** (overuse destroys hierarchy)
- **Large text letter-spacing**: Apply negative letter-spacing for 28pt or more (reduce visual density)
- **Body line-height**: 1.5~1.6× (optimal readability in a presentation environment)
- Don't use **`text-transform: uppercase`**: Do not apply capitalization to chart labels.
- **Output Language Rule**: The generated PPT follows the source Markdown's language. This skill does not translate content.

## 5) Slide layout

### 5.1 Basic specifications

| Item                                 | Value                              | Note                                 |
| ------------------------------------ | ---------------------------------- | ------------------------------------ |
| ratio                                | **16:9**                           | fix. 4:3 not supported               |
| Dimensions (Slide)                   | 13.333" × 7.5" (33.87cm × 19.05cm) | Standard 16:9                        |
| HTML Render Resolution               | **1920 × 1080 px**                 | Full HD. Large monitor compatible    |
| Margin (top, bottom, left and right) | **Minimum 0.7"** (1.78cm)          | Content area is placed inside only   |
| title area height                    | Top 15%                            | Slide top fixed position             |
| body area                            | Top 20% ~ Bottom 90%               | Below the title, above the footnotes |
| Footnotes/Source Area                | Bottom 5%                          | 8~10pt, right aligned                |

### 5.2 Content rules per slide

| Rule                        | Standard                       | On Excess                      |
| --------------------------- | ------------------------------ | ------------------------------ |
| **Number of topics**        | Up to **2**                    | Be sure to split slides        |
| **Bullet Point**            | Up to **4** (optimum 3)        | automatic split                |
| **Overlapping Bullets**     | Up to **1 level**              | 2nd stage or more → flattening |
| **Table Row**               | Up to **5 rows**               | Split or Move Appendices       |
| **Table Columns**           | Up to **4 rows**               | Extract only key columns       |
| **Number of lines of code** | Up to **12 lines**             | Split or extract only the core |
| **60 second rule**          | Understand slides ≤ 60 seconds | Minimize content               |
| **Continuous Text**         | Up to **2 photos in a row**    | 3rd switch to visual slide     |

### 5.3 Spacing between content (based on 8px grid)

> **All spacing is standardized to multiples of 8px**. (8, 16, 24, 32, 40, 48, 56, 64…)

| Between Elements                              | Spacing     | 8px multiple |
| --------------------------------------------- | ----------- | ------------ |
| Title → First Content                         | 0.4" (32px) | 32px (4×)    |
| bullet liver                                  | 0.2" (16px) | 16px (2×)    |
| Between content blocks (bullet → table, etc.) | 0.3" (24px) | 24px (3×)    |
| Image → Text (2-column layout)                | 0.3" (24px) | 24px (3×)    |
| Between small groups within sections          | 0.15" (8px) | 8px (1×)     |
| Between infographic elements                  | 0.2" (16px) | 16px (2×)    |

### 5.4 Sorting Rules

- **All text: left-aligned** (center-align only for title/section separation slides)
- **Title position: fixed between slides** (never move)
- **Grid Alignment**: All elements snap to a consistent grid

### 5.5 Layout Integrity — NEVER BREAK

> **Layout systems should never break**
> The rules below apply to all slides without exception, and if violated, the slides will be re-generated.

#### 5.5.1 Zero-Tolerance Rules

| rule                            | explanation                                                             | Action in case of violation      |
| ------------------------------- | ----------------------------------------------------------------------- | -------------------------------- |
| **No overflow**                 | All text/images must be within slide boundaries (0.7" margins)          | Reduce fonts or split slides     |
| **No overlap**                  | No element must overlap any other element (including z-index conflicts) | Rearrange or split elements      |
| **No deviation from alignment** | All elements must snap to the grid system                               | Grid Reorder                     |
| **Do not move title position**  | Slide titles are always fixed to the same coordinates                   | Force restoration of coordinates |
| **No margin encroachment**      | Content must not violate the 0.7" safe area                             | Collapse/Split Content           |

#### 5.5.2 Font size reduction cascade

When text overflow occurs, respond in the following order:

```
Step 1: Body font 18pt → 16pt (minimum limit)
Step 2: Subheader 20pt → 18pt
Step 3: Reduce the number of bullets (maximum 4 → 3 → 2)
Step 4: Force split slide
```

> **Title (24pt) and caption (12pt) are never reduced.**

#### 5.5.3 Element priority (in case of conflict)

| priority | element        | explanation                           |
| -------- | -------------- | ------------------------------------- |
| 1        | subject area   | Always in fixed position, never moved |
| 2        | Margin (0.7")  | Inviolable                            |
| 3        | body text      | Priority over image                   |
| 4        | Images/Charts  | collapsible                           |
| 5        | Caption/Source | Can be omitted first                  |

### 5.7 Slide Content Limits (SLIDES ARE NOT DOCUMENTS)

> **A slide with too much text is a badly made slide.**
> The problem is never "the text overflowed." The problem is "there's too much text."
> These limits define good slide design, not overflow thresholds.

#### 5.7.1 The Fundamental Rule

```
The audience should grasp the slide in ≤3 seconds of reading.
The presenter speaks the details. The slide shows keywords only.
If the audience is reading your slide, you've already failed.
```

#### 5.7.2 Content Limits Per Layout (DESIGN LIMITS, NOT OVERFLOW LIMITS)

| Layout              | Title |       Body       |    Bullets    | Words/Bullet | Total Slide Budget |
| ------------------- | :---: | :--------------: | :-----------: | :----------: | :----------------: |
| `title`             |  8w   |  10w (subtitle)  |       —       |      —       |        ~20w        |
| `executive-summary` |  6w   | 15w (conclusion) |       —       |      —       |        ~25w        |
| `section-divider`   |  6w   |        —         |       —       |      —       |        ~6w         |
| `text-body`         |  10w  |       40w        |       —       |      —       |        ~50w        |
| `bullet-list`       |  10w  |        —         | **3** (max 4) |    **7**     |        ~35w        |
| `image-text`        |  8w   |        —         |       3       |    **5**     |        ~25w        |
| `table`             |  8w   |        —         |       —       |      —       |         —          |
| `code`              |  8w   |        —         |       —       |      —       |         —          |
| `ai-hint`           |  8w   |       30w        |       —       |      —       |        ~40w        |
| `quote`             |   —   |       20w        |       —       |      —       |        ~20w        |
| `checklist`         |  8w   |        —         |    4 items    |      6       |        ~35w        |
| `closing`           |  8w   |        —         |    3 steps    |      5       |        ~25w        |
| `kpi-cards`         |  8w   |        —         |    4 cards    |  3 (label)   |         —          |
| `bar-chart`         |  8w   |        —         |    6 bars     |  5 (label)   |         —          |
| `process-flow`      |  8w   |        —         |    8 steps    |  3 (label)   |         —          |
| `timeline`          |  8w   |        —         |    6 items    |  4 (event)   |         —          |
| `comparison`        |  8w   |        —         |    4/side     |      6       |         —          |
| `icon-grid`         |  8w   |        —         |    6 cells    |   5 (desc)   |         —          |
| `funnel`            |  8w   |        —         |   5 stages    |  3 (label)   |         —          |

**"Total Slide Budget"** = Title + ALL body text combined. If the entire slide exceeds this word count, the slide is over-written.

#### 5.7.3 CJK Multiplier

| Language | Multiplier | Example: 7-word bullet becomes |
| -------- | :--------: | :----------------------------: |
| English  |    1.0×    |            7 words             |
| Korean   |    0.7×    |       5 단어 (~12 음절)        |
| Japanese |    0.7×    |              5 語              |
| Chinese  |   0.65×    |             4-5 字             |

#### 5.7.4 Bullet = Keyword Fragment

```
A bullet is NOT a sentence. It is a keyword fragment.

❌ "We improved processing speed from 3 seconds to 0.8 seconds"  (11 words — sentence)
✅ "처리 속도: **3s → 0.8s**"  (keyword fragment)

❌ "Adopted MSA architecture for independent deployment"  (7 words — still a sentence)
✅ "MSA 도입 → 독립 배포"  (keyword fragment)

Rule: If it has a subject + verb + object, it's a sentence. Rewrite.
```

#### 5.7.5 When Content Exceeds Limits

```
The content is too much. Not the slide.

1. Distill: Remove filler, rewrite as keyword fragments
2. Split: Create 2 focused slides instead of 1 crowded slide
3. Appendix: Move supporting data, keep only conclusion in body
4. Merge: If a section has too little substance, merge with adjacent

NEVER: Reduce font size to fit more text. That's treating the symptom.
```

### 5.6 Automated Layout Validation

After generating each slide, it automatically verifies:

| Check           | Method                                                                      | On Failure                         |
| --------------- | --------------------------------------------------------------------------- | ---------------------------------- |
| boundary check  | Calculate Awareness if all elements (x, y, w, h) are within the safe region | ReGenerate                         |
| Overlap check   | Check whether a pair of elements intersects the bounding box                | Re-Generate after relocation       |
| Text truncation | Compare actual height vs allocated area after text rendering                | Font reduction cascade             |
| grid sort       | Element coordinates are snapped to grid points                              | Coordinate correction              |
| image ratio     | Make sure there is no distortion of the original ratio                      | Resize after restoring proportions |

> If verification fails, regenerate\*\* up to 3 times. If it fails even after 3 attempts, take the best result + log warnings.

### 6.7 Slide flow rules

#### 6.7.1 Avoid continuous text (MAX-2-TEXT)

After **2 consecutive** text-only slides (`text-body`, `bullet-list`), the third slide must be converted to a visual slide:

| conversion target                    | condition                          |
| ------------------------------------ | ---------------------------------- |
| Infographics (KPI, Bar, Donut, etc.) | When matching data patterns        |
| `icon-grid`                          | Category List Personality Content  |
| `comparison`                         | Comparable Structure               |
| `image` / `image-text`               | When relevant images are available |

> If no visualization is possible, use `quote` layout to give visual rhythm by emphasizing key sentences.

#### 6.7.2 Early deployment of infographics (FRONT-VISUAL)

Place at least one infographic in the **first 30%** of all slides:

- Move slides with high visual impact (KPI Cards, Bar Chart, Comparison) forward
- Recommended placement of visualizations in first section immediately after Title + Executive Summary

#### 6.7.3 Automatic appendix separation (AUTO-APPENDIX)

Detailed data is separated from the text and moved to the appendix section:

| Appendix Move to                      | body replacement                              |
| ------------------------------------- | --------------------------------------------- |
| Detailed table with more than 6 rows  | 3 row summary table + "Details: see appendix" |
| QA Checklist                          | Core 3 items only + "Full list: see appendix" |
| Dependencies/Technology Stack Details | Summary of key points only                    |
| Reference data/original figures       | Keep only core KPI body                       |

The appendix is ​​placed after the `appendix-divider` slide, and can be used in the "A1, A2..." format separately from the main slide number.

## 8) Bullet-Point Style Rules

### 8.1 Slide title = Action title

All slide titles must be **complete sentences containing a conclusion**:

| ❌ Subject-type titles (prohibited) | ✅ Action title (required)                                                      |
| ----------------------------------- | ------------------------------------------------------------------------------- |
| Market Status                       | Domestic market growing 12% per year, expected to double in size within 3 years |
| Competitor Analysis                 | Gain an advantage over competitors in 4 out of 6 core criteria                  |
| technology stack                    | Processing speed can be improved by 3 times with Go + PostgreSQL combination    |

### 8.2 Bullet writing rules

```
[Action title — up to 15 words, complete sentences including verbs]
├── • Key point 1 — Include numbers/data
│ └── ◦ Secondary evidence (indent, small size)
├── • Key point 2 — Include numbers/data
└── • Key point 3 — Include numbers/data

[Source: Data source, year] ← Must be indicated
```

> **Bullet count rule**: Optimum 3 per slide, maximum 4. 5 or more must be split.

### 8.3 Text writing principles

| Principle                | Rule                                        | Example                                                 |
| ------------------------ | ------------------------------------------- | ------------------------------------------------------- |
| **Numerical precedence** | Place numbers in front of bullets           | “Sales increased by 23%” (O) / “Sales increased” (X)    |
| **Parallel Structure**   | All bullets have the same grammatical form  | Noun-type unification or verb-type unification          |
| **1 bullet 1 idea**      | No “and/and” in bullets.                    | Separate into 2 bullets                                 |
| **Avoid sentence type**  | No endings such as “~ did” and “is”         | Noun ending ("increase", "introduce", "apply")          |
| **Core Bold**            | The 1 most important number in Bullet: Bold | “Improved processing speed **3 seconds → 0.8 seconds**” |

## 8.5) Keyword Extraction & Slide Content Guidelines

> **Keywords are the DNA of every slide.**
> Without proper keyword extraction, slides become text walls.
> This section defines how extracted keywords translate to visual design.

### 8.5.1 Keyword-to-Design Mapping

| Keyword Type                           | Visual Treatment     | CSS/Style                                                                          |
| -------------------------------------- | -------------------- | ---------------------------------------------------------------------------------- |
| `accent_candidate` (1 per slide)       | Bold + Accent color  | `font-weight: 700; color: #D94F4F;`                                                |
| `supporting_keyword` (max 2 per slide) | Bold only            | `font-weight: 700; color: #1A1A1A;`                                                |
| `kpi_metric`                           | Large number display | `font-size: 56px; font-weight: 700; font-variant-numeric: tabular-nums;`           |
| `primary_keyword` → Action title       | Slide title rewrite  | `font-size: 24pt; font-weight: 700;` — must be a complete sentence with conclusion |

### 8.5.2 Action Title Construction from Keywords

Every slide title MUST be an action title derived from `primary_keyword`:

```
Formula: [Quantified Result/Fact] + [Verb] + [Impact/Conclusion]

primary_keyword: "processing speed 3x improvement"
→ Action title: "Processing speed improves 3x, cutting average response from 3s to 0.8s"

primary_keyword: "MSA architecture adoption"
→ Action title: "MSA architecture adoption enables independent scaling per service"

primary_keyword: "failure rate reduction"
→ Action title: "System failure rate drops 73% after migration to new platform"
```

**Title word limit**: Max 15 words (Korean: ~25 characters). If the constructed title exceeds this, prioritize the numeric outcome.

### 8.5.3 Accent Word Placement Rules

| Rule                    | Specification                                                                      |
| ----------------------- | ---------------------------------------------------------------------------------- |
| **Exactly 1 per slide** | Never 0, never 2+                                                                  |
| **Word-level only**     | Apply to specific number/phrase, never to entire sentence                          |
| **Bold required**       | Accent color (`#D94F4F`) always paired with `font-weight: 700`                     |
| **Position**            | Place within body text where the eye naturally flows (1st or 2nd bullet preferred) |
| **Selection priority**  | Numbers > Percentages > Comparisons > Decision keywords                            |

### 8.5.4 Slides Without Identifiable Keywords

If keyword extraction finds no clear `primary_keyword` for a section:

1. **Re-analyze**: Look for implicit keywords (topic nouns, action verbs, structural markers)
2. **If still none**: The section likely contains low-value content → merge with adjacent section or move to appendix
3. **Never generate a slide without a clear keyword focus**

### 15.6 Content→Visualization Automatic Map Rule

#### 15.6.1 Core principles

- The mode is based on **AGGRESSIVE**.
- If the pattern matches, it must be converted into a visualization template.
- Text fallback is only allowed under pattern matching failure or explicit override conditions.

#### 15.6.2 Pattern detection rules

| pattern id         | trigger condition                                                   | Visualization type                    | Example Input                                               | reliability |
| ------------------ | ------------------------------------------------------------------- | ------------------------------------- | ----------------------------------------------------------- | ----------- |
| `NUM-COMPARE`      | 3+ Each item includes figures (%, number of cases, amount)          | Horizontal Bar Chart (`.bar-chart-h`) | "Q1: 87%, Q2: 64%, Q3: 92%"                                 | High        |
| `PCT-BREAKDOWN`    | Percentage sum of 2-5 items is 90-110%                              | Donut Chart (`.donut-chart`)          | "APAC 42%, EMEA 31%, Americas 27%"                          | High        |
| `SEQ-STEPS`        | 3-8 sequential steps (number, arrow, then, step N)                  | Process Flow (`.process-flow`)        | "Input → Parse → Map → Generate → Output"                   | High        |
| `BEFORE-AFTER`     | Comparison of 2 categories (vs, existing/improved, before/after)    | Comparison (`.comparison`)            | "Legacy: 30 min manual / Skill: 1-3 min automated"          | High        |
| `KEY-METRIC`       | 1-4 key figures + labels + modifiers                                | KPI Cards (`.kpi-grid`)               | "Conversion Success Rate 95%, Structure Accuracy 100%"      | High        |
| `CATEGORY-LIST`    | 4-8 short items (≤6 words each), categorical in nature, no numbers. | Icon Grid (`.icon-grid`)              | "Dev Lead, Planner, CTO/VP, AI User"                        | Medium      |
| `CHRONOLOGICAL`    | 3+ Events by Date/Time/Phase + Chronological Order                  | Timeline (`.timeline`)                | “Phase 1: MVP, Phase 2: Chart, Phase 3: AI”                 | Medium      |
| `NARROWING-STAGES` | Quantity decreases in steps 3-6 (Inflow → Conversion → Purchase)    | Funnel (`.funnel`)                    | "Awareness 10K → Interest 7.5K → Decision 5K → Action 2.5K" | Medium      |

#### 15.6.3 Priority Decision

If multiple patterns are matched simultaneously, the final template is decided in the order below.

1. Prioritize highly reliable patterns (High)
2. In case of a reliability tie, priority is given to visualizations with less text.
3. If the score is still tied, the fixed priorities below apply.

`NUM-COMPARE` > `PCT-BREAKDOWN` > `KEY-METRIC` > `SEQ-STEPS` > `BEFORE-AFTER` > `CHRONOLOGICAL` > `CATEGORY-LIST` > `NARROWING-STAGES`

#### 15.6.4 Conversion Exception (Override)

- If there is a `<!-- keep-text -->` annotation in Markdown, that block will skip visualization conversion.
- For heterogeneous data tables with more than 5 columns or 8 rows, the original table is maintained.
- Reference tables that require accurate cell value references maintain the original table.

#### 15.6.5 Visualization slide constraints

- The text is limited to 40 words or less. (excluding chart labels/data)
- Bullets or labels are limited to 7 words per item.
- Chart categories are limited to a maximum of 5.
- Secure at least 20% of the total area of ​​the slide as blank space.
- Only one visualization is allowed per slide. (2 charts prohibited)
- The action title is required and must be written as a complete sentence, including verbs, of less than 15 words.

#### 15.6.6 Data Extraction Rules

- Numbers: Extract all numbers and preserve units. (`%`, `$`, `x`, `pt`)
- Label: Use the shortest possible form and abbreviate if it exceeds 7 words.
- Source: Preserve the original data source as a caption.

### 16.3 Design compliance rules when using external skills

All External Skill Output **MUST** comply with the following:

1. **Color**: Use only the palette from Section 2. No random colors
2. **Font**: Pretendard (+ fallback chain). If a different external skill uses a different font, it is replaced in post-processing.
3. **Layout**: 16:9, margins 0.7" or more
4. **Text Style**: Modified. Sentential output is converted and reorganized in a modified form.
5. **Highlight**: `#D94F4F` word level only. If an external skill adds color emphasis, remove it from post-processing

> **Principle**: External skills are only used as “data/content sources”, and the final design is always governed by this design-spec.

## 17) Environmental Detection & Model Guidance (IDE Detection & Model Guidance)

### 17.1 Core principles

> **Gemini Pro** (`gemini-2.5-pro`) model is required to generate AI images.
> The model conversion method varies depending on the IDE environment.

| Environment               | Image Generation Model  | PDF Rendering Model           | Model Switching                   |
| ------------------------- | ----------------------- | ----------------------------- | --------------------------------- |
| **Cursor** (non-OpenCode) | Gemini Pro              | Gemini Pro (All)              | Manually switch users (pre-check) |
| **OpenCode**              | Gemini Pro (background) | Maintain user selection model | Automatic background task         |

### 17.2 Cursor IDE Workflow

In Cursor and other non-OpenCode environments, models cannot be switched at runtime.
Therefore, you must ask the user to switch models **before starting the task**.

#### Required pre-message (Blocking)

Before starting PPT conversion, **MUST** output the following message and wait for user confirmation:

```
⚠️ Gemini Pro model selection required

This PPT conversion task requires the Gemini Pro model to generate AI images.
Please switch your current model to Gemini Pro (gemini-2.5-pro) before continuing.

How to switch models: [IDE Settings] → [Select Model] → Select Gemini Pro

After completing the conversion, please input “Continue” or “Proceed.”
```

- **Never** start the conversion until the user sends a confirmation response
- Check keywords: `"continue"`, `"proceed"`, `"ok"`, `"yes"`, `"done"`

### 17.3 OpenCode Workflow

In OpenCode, only image generate is executed as a separate model through a background task.

#### Main pipeline (user-selected model)

```
MD Parse → Slide Map → HTML Generate → PDF Rendering → Layout Verification
```

#### Generate image (background — Gemini Pro)

```
Step 1: Main Pipeline Generate a list of slides that require images
Step 2: Create a list of image Generate prompts
Step 3: Spawn background task (Gemini Pro model)
        → task(run_in_background=true)
Step 4: Run NanoBanana Pro /generate in the background
Step 5: Save Generate results to assets/
Step 6: The main pipeline collects results using background_output() and inserts them into HTML slides for PDF rendering.
```

### 17.4 Environmental Sensing Methods

| Detection Criteria                | OpenCode     | Cursor / Other   |
| --------------------------------- | ------------ | ---------------- |
| Availability of `task()` function | ✅ Available | ❌ Not available |
| Background task support           | ✅           | ❌               |
| Model Runtime Switching           | ✅           | ❌               |

Detection logic: Determine OpenCode/non-OpenCode by whether background task API is available.
If not available → Cursor workflow (17.2) applied.

## 19) Visual Blueprint Schema

> **Every slide gets a Visual Blueprint before rendering begins.**
> The blueprint drives layout selection, image strategy, and emphasis placement.

### 19.1 Source of Truth

- This schema is aligned with SKILL.md Phase 3 and is authoritative for design-to-render handoff.
- Phase 2 provides role and message inputs; Phase 3 converts them into layout-ready blueprint objects.
- Rendering in Phase 4 must not bypass blueprint decisions except for hard-gate remediation.

### 19.2 VisualBlueprint Schema (Per Slide)

```yaml
VisualBlueprint:
  slide_id: number
  role: string # from Phase 2 narrative role
  message: string # from Phase 2 distilled message
  visual_intent: string # dramatic-stat, data-proof, narrative-image, action-items, etc.
  eye_flow:
    first: string # hero_number | image | headline | chart
    second: string
    third: string
  composition:
    type: string # hero-metric, split-image-text, evidence-bullets, single-statement, ...
    dominant_element: string # number | image | text | chart
    template_class: string # CSS root class from Section 18 and Section 15
  image_strategy:
    need: enum [original-md, chart, ai-generated, none]
    treatment: enum [full-bleed, background-10%, background-15%, left-50%, top-30%, chart-centered, none]
    prompt_seed: string # insight-based phrase, never keyword-only
    cache_lookup:
      image_key: string
      hit: boolean
  emphasis:
    accent_word: string
    bold_elements: string[]
  template: string # final layout template key used by renderer
```

### 19.3 DeckRhythm Validation Rules

```yaml
DeckRhythm:
  max_consecutive_same_density: 2
  max_consecutive_same_dominant: 2
  mood_arc_required: true
  visual_variety_score: ">= 0.6"
```

- `max_consecutive_same_density`: no more than 2 dense text-heavy slides in sequence.
- `max_consecutive_same_dominant`: no more than 2 slides where the same dominant element repeats.
- `mood_arc_required`: narrative should progress tense -> hopeful -> confident.
- `visual_variety_score >= 0.6`: measured across composition switches, dominant element shifts, and image treatment diversity.

### 19.5 Eye-Flow Patterns

| Pattern        | Use Case                        | Ordered Eye Flow                           |
| -------------- | ------------------------------- | ------------------------------------------ |
| `z-pattern`    | Default mixed-content slides    | headline -> visual proof -> action/insight |
| `f-pattern`    | Text-heavy evidence slides      | headline -> left bullets -> right support  |

### 19.6 Composition Selection Decision Tree

```text
1) Determine visual_intent from Phase 2 role + message
2) If visual_intent = dramatic-stat:
     - If one metric dominates -> hero-metric

3) If visual_intent = data-proof:
     - If multi-KPI + chart needed -> data-dashboard
     - If direct category comparison -> bar_chart/comparison
4) If visual_intent = narrative-image:
     - If text overlay <= 2 lines -> narrative-image
     - Else -> split-image-text
5) If visual_intent = action-items -> action-close/closing
6) Run DeckRhythm validation; if violation, choose alternate recipe with different dominant_element
```

### 20.4 Layering and Readability Constraints

- Background treatments (`background-10%`, `background-15%`) must remain behind text (`z-index: 0`) with text layers at `z-index: 1+`.
- Overlay text blocks should use solid or high-opacity white backgrounds when contrast falls below readable thresholds.
- No treatment may introduce motion, transitions, or interactive behavior because output is PDF-first.
- Color grading and filters must stay minimal and cannot introduce colors outside Section 2 palette rules.

## 21) Design Token System

### 21.1 Three-Tier Architecture

| Tier          | Purpose                                                         | CSS Exposure                       |
| ------------- | --------------------------------------------------------------- | ---------------------------------- |
| **Primitive** | Raw palette values (neutral_50 through neutral_900, accent_500) | Not exposed as CSS vars            |

### 21.3 Backward Compatibility

All CSS uses `var(--token, fallback)`:

```css

```

If no theme is injected, the hardcoded fallback ensures correct rendering.

## 23) Layout Variant System

23 layout types with 2-3 variants each (69 total) in `design/variants.py`.

### 23.1 Variant Properties

Each `LayoutVariant` specifies:

- `dominant_element`: text | image | data | whitespace | mixed
- `content_density`: sparse | medium | dense
- `split_ratio`: "50:50" | "60:40" | "40:60" | None
- `css_overrides`: dict of CSS property overrides for `.content`

### 23.2 Rhythm-Based Selection

`select_variant()` scores candidates to maximize visual rhythm:

| Factor                           | Score          | Purpose                   |
| -------------------------------- | -------------- | ------------------------- |
| Same variant_key as previous     | -4.0           | Prevent repetition        |
| 3+ consecutive same dominant     | -5.0           | Force alternation         |
| 3+ consecutive same density      | -3.5           | Prevent monotony          |
| Different dominant from previous | +2.0           | Reward variety            |
| Different split_ratio            | +1.25          | Reward composition change |
| Content-appropriate density      | +0.75 to +1.25 | Match content volume      |
