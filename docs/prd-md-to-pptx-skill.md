## 1) Background & Motivation

### 1.1 Problem Definition

MaraudersMapMD is an AI-native Markdown preview extension that automatically generates AI-friendly artifacts such as document structure (AI Map), section separation (Section Pack), and search indices (Search Index). However, to **share these structured Markdown documents with non-developer stakeholders** or **convert them for meetings/presentations**, users must manually compose presentation files.

### 1.2 Opportunity

MaraudersMapMD's Markdown already contains structured information including **clear heading hierarchies**, **section separation**, **AI Hint blocks**, **tables/lists/code blocks**, etc. Leveraging this structure enables:

- **Auto Slide Mapping**: Heading hierarchy → Slide structure
- **Content Type Recognition**: Tables → Table slides, Code → Code slides, Images → Image slides
- **AI Hint Priority Handling**: Extract `[AI RULE]`, `[AI DECISION]`, etc. as key slides
- **Design Automation**: Auto-select layouts/colors matching content type

### 1.3 Core Value Proposition

| Current Workflow                                            | With This Skill                                            |
| ----------------------------------------------------------- | ---------------------------------------------------------- |
| Read MD → Manually create PPT (30 min–2 hours)              | "Convert this MD to PPT" — one command (1–3 min)           |
| Analyze structure → Allocate slides → Design → Copy content | Auto structure analysis → Auto slide mapping → Auto design |
| AI Hints missed                                             | AI Hints auto-highlighted on dedicated slides              |

## 2) Goals / Non-Goals

### 2.1 Goals

1. **One-Click Conversion**: Generate presentation-quality PDF from just a Markdown file path
2. **Structure Preservation**: Accurately reflect MaraudersMapMD's heading hierarchy/section structure in slide structure
3. **Content-Type-Optimized Rendering**: Convert text, tables, code, images, and lists into their optimal slide layouts
4. **Visualization Auto-Mapping**: Detect patterns in numeric data, comparisons, sequential steps, etc. and auto-convert to infographics (charts, KPI cards, timelines, etc.) — 8 visualization types supported (see `design-spec.md` Section 15.6–15.7)
5. **AI Hint Special Handling**: Convert `[AI RULE]`, `[AI DECISION]`, `[AI CONTEXT]`, etc. into visually emphasized slides
6. **Design Quality**: Professional quality with just the default theme — no additional design work needed
7. **Existing Infrastructure Reuse**: Use Playwright for direct HTML→PDF rendering to minimize development cost
8. **Korean/CJK Full Support**: Consistent CJK text handling aligned with MaraudersMapMD's `koreanWeighted` token estimation mode

### 2.2 Non-Goals

- Universal support for all Markdown variants (GFM, MDX, RST, etc.) — focused on MaraudersMapMD-style MD
- Advanced animation/transition customization (basic transitions only)
- Bidirectional conversion (out of scope)
- Real-time sync (auto-update PPT when MD changes)
- Template designer/editor

## 6) Slide Mapping Strategy

### 6.1 Heading-Based Slide Separation Rules

MaraudersMapMD generates Section Packs based on H2 headings. This Skill uses the same strategy, optimized for presentation flow.

````
[MD Structure]                [Slide Structure]
─────────────                ──────────────────
# Document Title         →   Slide 1: Title slide
  (preamble content)     →   Slide 2: Overview/preamble slide (if content exists)

## Section A             →   Slide 3: Section divider slide "Section A"
  paragraph...           →   Slide 4: Text content slide
  - bullet list          →   Slide 5: Bullet point slide (split by content volume)
  | table |              →   Slide 6: Table slide

## Section B             →   Slide 7: Section divider slide "Section B"
  > [AI DECISION] ...    →   Slide 8: AI Hint highlight slide
  ```code```             →   Slide 9: Code slide
  ![img](path)           →   Slide 10: Image slide
````

### 6.2 Slide Split Rules

| Rule                     | Condition                       | Action                                     |
| ------------------------ | ------------------------------- | ------------------------------------------ |
| **H2 Split**             | H2 heading encountered          | Create new section divider slide           |
| **Content Length Split** | Bullet points > 5               | Split into 2+ slides (bullet-point style)  |
| **Type Switch Split**    | Text → Table, Text → Code, etc. | New slide on content type change           |
| **Image Split**          | Image encountered               | Dedicated image slide or image+text layout |
| **AI Hint Split**        | AI Hint block encountered       | Independent highlight slide                |
| **Table Split**          | Table rows > 6                  | Split across slides or summarize           |

### 6.3 Slide Layout Types

| Layout            | Purpose                  | Composition                                          |
| ----------------- | ------------------------ | ---------------------------------------------------- | ---- |
| `title`           | Document title           | Large title + subtitle (if any) + date               |
| `section-divider` | H2 section start         | Section title + icon/number                          |
| `text-body`       | General text             | Title + body text                                    |
| `bullet-list`     | Bullet/numbered list     | Title + bullet points (max 6/slide)                  |
| `table`           | Tabular data             | Title + table (HTML/CSS native table rendering)      |
| `code`            | Code block               | Title + monospace code (dark background)             |
| `image`           | Image-focused            | Image (full or half layout)                          |
| `image-text`      | Image + description      | 2-column: Image                                      | Text |
| `quote`           | Blockquote               | Large quotation marks + quote text                   |
| `ai-hint`         | AI Hint block            | Icon + Hint type badge + content (emphasized colors) |
| `checklist`       | Task list                | Title + checkbox list                                |
| `closing`         | Final slide              | "Thank You" or user-specified                        |
| `kpi-grid`        | Key metric cards         | 1–4 KPI cards (number + label + delta)               |
| `bar-chart-h`     | Numeric comparison chart | Horizontal bar chart (CSS flexbox)                   |
| `donut-chart`     | Proportion chart         | Donut chart (CSS conic-gradient)                     |
| `process-flow`    | Sequential process       | 3–8 step horizontal flow (arrow-connected)           |
| `timeline`        | Chronological events     | Horizontal timeline (milestones + dates)             |
| `comparison`      | Comparison layout        | 3-column grid (Before \| VS \| After)                |
| `icon-grid`       | Category overview        | 2x2–3x3 icon + text grid                             |
| `funnel`          | Stage-based reduction    | Top-to-bottom narrowing funnel chart                 |

### 7.0 Seven Design Principles

1. **Minimal Colors** — 3 or fewer colors (Background 60% + Text 30% + Accent 10%)
2. **Readability First** — All design decisions are based on readability
3. **Mandatory Versioning** — Output `v{major}.{minor}_filename.pdf` with each generation
4. **Clear Visual Hierarchy** — Differentiate via font size/weight, not color dependency
5. **Active Image Usage** — Generate or download from web; prioritize visuals over text
6. **High-Resolution Widescreen** — 16:9, 1920×1080 baseline
7. **1–2 Topics Per Slide** — Bullet-point, quantitative expression-oriented

## 8) Technical Architecture

### 8.1 Conversion Pipeline

```
[Input]     [Env Detect]   [Parse]        [Map]          [Image Gen]    [HTML Gen]    [PDF Render] [Verify]      [Output]
 .md   →   IDE Detect  →  MD Structure → Slide     →  NanoBanana  →  Playwright  →  .pdf     →  Layout     →  File
 file      Model Check     Parse         Mapping      Pro/Gemini     Workflow      Render      Integrity     Output
```

### 8.2 Phase Details

#### Phase 1: Markdown Parsing

Markdown structure analysis referencing MaraudersMapMD's parsing logic:

````
1. Split full text into lines
2. Track code block boundaries (```) to ignore headings inside code
3. Extract H1 → document title
4. Separate sections by H2 (create Section[])
5. Classify content types within each section:
   - Bullet/numbered list blocks
   - Table blocks
   - Code blocks (with language tags)
   - Image references
   - AI Hint blocks
   - Blockquote blocks
   - Plain text paragraphs
6. Preserve order between content blocks
````

#### Phase 2: Slide Mapping

```
1. Create title slide (extracted from H1 + preamble)
2. Iterate each H2 section:
   a. Create section divider slide
   b. Process content blocks sequentially:
      - Select layout by block type
      - Split slides by content volume
      - Special handling for AI Hint blocks
3. Create closing slide (optional)
4. Complete slide number mapping
```

#### Phase 3: HTML Generation & PDF Rendering

Using Playwright-based PDF rendering:

```
1. Generate each slide as an HTML file:
   - 1920 x 1080 px (16:9, Full HD) — large screen compatible
   - Apply design/theme via CSS (design-spec.md compliant)
   - Use Pretendard font (fallback: Apple SD Gothic Neo → Malgun Gothic → Noto Sans KR)
2. Render HTML slides to PDF via Playwright:
   - Combine all slide HTMLs into a single HTML document with `page-break-after: always` between slides
   - Open combined HTML in headless browser (1920×1080 viewport)
   - Render to ONE unified PDF via `page.pdf({ width: '1920px', height: '1080px', printBackground: true, preferCSSPageSize: true })`
   - Result: single PDF file with N pages (one page per slide)
3. Tables and charts rendered natively in HTML/CSS — no separate conversion needed
4. Save resulting PDF file
```

## 9) Conversion Rules — Detail

### 9.1 Text Content

| MD Element          | PDF Conversion                                         |
| ------------------- | ------------------------------------------------------ |
| `# H1`              | Title slide main text (36pt, Bold)                     |
| `## H2`             | Section divider slide title (32pt, Bold)               |
| `### H3`            | Content slide sub-header (24pt, Bold)                  |
| `#### H4+`          | Emphasized text in body (20pt, Bold)                   |
| Plain paragraph     | Body text (18pt)                                       |
| `**bold**`          | Bold formatting                                        |
| `*italic*`          | Italic formatting                                      |
| `` `inline code` `` | Monospace + gray background                            |
| `[link](url)`       | Converted to text (link text only, footnote if needed) |

### 9.2 List Content

```
Bullet Lists:
- Max 5 per slide (bullet-point style, configurable)
- Auto-split when exceeding 6
- Nested lists: only 1 level of depth supported (indent-based)
- 2+ levels of nesting are flattened

Numbered Lists:
- Same rules as bullet lists
- Numbers preserved (continuous numbering across splits)

Task Lists:
- Checkbox icons (☑/☐) + text
- Visual distinction for completed/incomplete (strikethrough or color difference)
```

### 9.3 Table Content

```
Small Tables (≤5 columns, ≤6 rows):
- Generate native table with HTML/CSS table rendering
- Emphasize header row (background color + Bold)
- Auto-calculate column widths

Large Tables (>5 columns or >6 rows):
- Split across multiple slides
- Or extract key columns/rows into summary table
- Add footnote referencing original data
```

### 9.4 Code Blocks

```
Code Slides:
- Dark background (#1E1E1E)
- Light text (#D4D4D4)
- JetBrains Mono 13pt (fallback: Courier New)
- Language tag displayed (top-right badge: #555555 background + #FFFFFF text)
- Max 12 lines/slide — split or abbreviate if exceeded
- Rounded corners 8px
- Syntax highlighting colors applied from base color set (keywords, strings, comments differentiated)
```

### 9.5 Images

```
Image Handling:
- Local images (./assets/*.png etc.): Insert file directly
- Remote images (https://...): Download from URL then insert
- Data URI images: Decode then insert
- AI-generated images (photorealistic content only):
  - NanoBanana Pro: /generate "prompt" --styles="photorealistic" → nanobanana-output/ → copy to assets/
  - Gemini API Fallback: POST gemini-2.5-flash-image → decode base64 PNG → save to assets/
  - Scope: Photorealistic photos/illustrations only (not charts/diagrams/icons)
  - Quality: 1920×1080px, PNG, under 5MB
  - OpenCode: Generate as background task (Gemini Pro model)
  - Cursor: Generate directly in main pipeline (full Gemini Pro model)

Layout Decision:
- Image only: Full slide image
- Image + text: 2-column layout (Image 60% | Text 40%)
- Multiple consecutive images: Grid layout (2x2 or 1x3)
```

### 9.6 AI Hint Blocks

```
Recognition Patterns:
- > [AI RULE] text
- > [AI DECISION] text
- > [AI NOTE] text
- > [AI CONTEXT] text

Slide Conversion:
- Separated as independent slides
- Type-specific backgrounds and badges (see Section 7.2)
- Large text (24pt) for emphasis
- Icons: Type-appropriate emoji or SVG icons
  - RULE: ⚠️ / Warning icon
  - DECISION: ✅ / Check icon
  - NOTE: 📝 / Note icon
  - CONTEXT: 🔍 / Magnifying glass icon
```

### 9.7 Blockquotes

```
General Blockquotes (> quote):
- Large quotation mark graphic
- Italic text
- Left color bar (primary color)

Non-AI-Hint Blockquotes:
- Standard quote slide layout
- Source attribution displayed at bottom if available
```

## 10) Workflow Details (SKILL.md Body Structure)

### 10.1 Full Workflow

````
Phase 0: Input Contract + Environment Detection
  - Capture InputContract: audience, goal, time_minutes, slide_budget, tone, cut_policy
  - Detect IDE environment (OpenCode vs Cursor/Others)
  - OpenCode: Check background task API → Prepare image generation pipeline
  - Cursor/Others: Use native image gen (Nano Banana Pro) — no model switch needed

Phase 1: Semantic Analysis (MD Parsing + Section Cards)
  - Verify MD file path or receive inline MD text
  - Parse markdown: H1→title, H2→section boundaries, H3→sub-headers/splits
  - Generate SectionCard per H2 section (12 fields: source_section, claim, role, stakes, must_keep, insight, headline, evidence, accent_candidate, kpi_metrics, source_lines, confidence)
  - Markdown sanitization: remove display tokens (#, -, *, ```)
  - Visual content detection (AGGRESSIVE mode): auto-detect chart/infographic candidates

Phase 2: Narrative Architecture
  - Determine story arc: problem-solution | journey | comparison | showcase
  - Assign 7 narrative roles to slides: hook, problem, insight, solution, proof, impact, cta
  - Build slide plan with sequence, role assignments, source linkage
  - Content distillation: condense to <=50w EN / 35w KR per slide
  - Dual output routing: deck | appendix | speaker_notes | cut (coverage_pct must = 100%)
  - Executive summary auto-insert for 10+ slide decks
  - Slide flow optimization: MAX-2-TEXT, FRONT-VISUAL, AUTO-APPENDIX, SHORT-SECTION-MERGE

Phase 3: Visual Blueprint
  - Generate per-slide VisualBlueprint: eye_flow, composition, image_strategy, emphasis
  - Validate Deck Rhythm: density variation, mood arc, visual_variety_score >= 0.6
  - Map visual intent → layout recipe (dramatic-stat→hero-metric, etc.)

Phase 4: Rendering (HTML + Image + PDF)
  - 3-priority image system:
    Priority 1: Original MD images → copy to assets/, absolute path reference
    Priority 2: HTML code generation → charts (templates/charts/), compositions → Playwright screenshot
    Priority 3: LLM image generation → insight-based prompt → Native gen / task() / HTML fallback
  - Image Manifest (assets/image-manifest.json) — tracks type, prompt, generator, visual_intent, hashes, dimensions, file_size_bytes per asset
  - Individual HTML per slide, CSS inline, 16:9 at 1920x1080px
  - PDF rendering via Playwright
  - Tables rendered natively in HTML/CSS

Phase 5: Verification + Output
  - Hard gates: text_only_slide_ratio=0%, token_leakage=0, coverage_pct=100%
  - Layout integrity: no overflow, no overlap, margins >=0.7"
  - Output: v{M}.{m}_{filename}.pdf + _appendix.pdf + assets/image-manifest.json + .coverage-report.json
  - Diagnostic report in completion message
````

## Appendix B: Playwright PDF Rendering Integration

### HTML→PDF Workflow

1. Create individual HTML per slide during generation (1920×1080, 16:9)
2. Combine all slide HTMLs into a single HTML document with CSS `page-break-after: always` between slides
3. Launch Playwright headless browser
4. Open the combined HTML and render to ONE unified PDF via `page.pdf({ width: '1920px', height: '1080px', printBackground: true, preferCSSPageSize: true })`
5. Result: single PDF file with N pages — individual per-slide PDFs are NEVER the final output
6. Tables, charts, and images rendered natively in HTML/CSS

### Design Principles (from rendering skill)

- Use only web-safe fonts
- Clear visual hierarchy (size, weight, color)
- Readability: strong contrast, appropriate text size
- Consistency: repeated patterns, spacing, visual language
